¿Qué es un Evento?

Un evento es una señal de que algo ha ocurrido. Puede ser una acción del usuario (como un clic) o una acción del navegador (como terminar de cargar la página).

// Acciones del Usuario:
// - Hacer clic en un botón ('click')
// - Mover el ratón ('mousemove')
// - Pulsar una tecla ('keydown')

// Acciones del Navegador:
// - La página ha terminado de cargar ('load')
// - Un video ha empezado a reproducirse ('play')

El Flujo de la Gestión de Eventos

El proceso para hacer una página interactiva siempre sigue tres pasos:

1. Seleccionar el elemento HTML que originará el evento.
2. Escuchar un tipo de evento específico en ese elemento.
3. Reaccionar ejecutando una función cuando el evento ocurra.

// 1. Seleccionar
const miBoton = document.querySelector('#mi-boton');

// 2. Escuchar y 3. Reaccionar
miBoton.addEventListener('click', function() {
  console.log('¡Botón pulsado!');
});

El Método: `addEventListener()`

Es la forma moderna, estándar y recomendada para registrar un "escuchador de eventos". Es más flexible que métodos antiguos como `onclick`.

elemento.addEventListener('tipoDeEvento', funcionManejadora);

// 'tipoDeEvento': Un string con el nombre del evento (ej: 'click').
// 'funcionManejadora': La función que se ejecutará. También se le
//                    llama "función de callback".
4 / 30

Ventajas de `addEventListener()`

A diferencia de `elemento.onclick`, podemos añadir múltiples "escuchadores" para el mismo evento en el mismo elemento sin sobreescribir los anteriores.

const boton = document.querySelector('#login-btn');

// Esto funciona perfectamente
boton.addEventListener('click', validarFormulario);
boton.addEventListener('click', enviarAnaliticas);

// Con el método antiguo, solo funcionaría el último
// boton.onclick = validarFormulario;
// boton.onclick = enviarAnaliticas; // ¡Sobreescribe el anterior!

Eventos de Ratón (Mouse)

Son los más comunes y se refieren a las interacciones con el puntero.

'click'       // Un solo clic.
'dblclick'    // Doble clic.
'mousedown'   // Se presiona el botón del ratón.
'mouseup'     // Se suelta el botón del ratón.
'mousemove'   // El puntero se mueve sobre el elemento.
6 / 30

`mouseover` vs `mouseenter`

Una distinción importante. `mouseover` se dispara también en los hijos (burbujea), mientras que `mouseenter` solo se dispara en el elemento padre.

const cajaPadre = document.querySelector('#padre');

// mouseover: Se dispara al entrar en #padre Y al entrar en #hijo
cajaPadre.addEventListener('mouseover', () => console.log('Over!'));

// mouseenter: Solo se dispara al entrar en #padre
cajaPadre.addEventListener('mouseenter', () => console.log('Enter!'));
// 'mouseout' y 'mouseleave' tienen la misma diferencia.
7 / 30

Eventos de Teclado (Keyboard)

Permiten reaccionar a la pulsación de teclas. Son esenciales para atajos, validaciones en tiempo real y juegos.

// Se dispara cuando una tecla es presionada.
document.addEventListener('keydown', function(event) {
  // 'event.key' nos dice qué tecla fue ("a", "Enter", "F5")
  if (event.key === 'Escape') {
    cerrarModal();
  }
});

// 'keyup': Se dispara cuando la tecla se suelta.
// 'keypress': Antiguo, mejor evitarlo.
8 / 30

Eventos de Formulario

Fundamentales para la validación y el envío de datos.

const miFormulario = document.querySelector('#registro');

// 'submit': Se dispara al intentar enviar el formulario.
miFormulario.addEventListener('submit', function(event) {
  // Evita que la página se recargue (acción por defecto)
  event.preventDefault();
  
  // Aquí iría nuestra lógica para enviar los datos con JS
  console.log('Formulario enviado sin recargar.');
});
9 / 30

Eventos de Inputs: `input` vs `change`

`input`: Se dispara inmediatamente cada vez que el valor del elemento cambia. Ideal para feedback en tiempo real.

`change`: Se dispara cuando el valor se "confirma", normalmente cuando el elemento pierde el foco (`blur`).

const campoTexto = document.querySelector('#usuario');

// Se ejecuta con cada letra que escribes
campoTexto.addEventListener('input', () => console.log('Escribiendo...'));

// Se ejecuta solo cuando sales del campo de texto
campoTexto.addEventListener('change', () => console.log('Valor confirmado.'));
10 / 30

Eventos de Foco: `focus` y `blur`

Permiten saber cuándo un usuario entra o sale de un elemento interactivo, como un campo de texto o un botón.

const input = document.querySelector('#mi-input');

// Cuando el usuario hace clic o tabula hacia el input
input.addEventListener('focus', () => {
  input.style.border = '2px solid blue';
});

// Cuando el usuario hace clic o tabula fuera del input
input.addEventListener('blur', () => {
  input.style.border = '1px solid grey';
});
11 / 30

Eventos de Documento y Ventana

Eventos que se aplican a toda la página o a la ventana del navegador.

// 'DOMContentLoaded': Se dispara cuando el HTML ha sido cargado
// y el árbol del DOM está listo. Es el mejor momento para
// ejecutar nuestro script de manipulación del DOM.
document.addEventListener('DOMContentLoaded', inicializarApp);

// 'load': Espera a que TODO (imágenes, CSS, etc.) cargue. Más lento.
window.addEventListener('load', () => console.log('Todo cargado.'));
12 / 30

Eventos de `scroll` y `resize`

Permiten reaccionar al desplazamiento de la página o al cambio de tamaño de la ventana.

// 'scroll': Se dispara continuamente mientras el usuario hace scroll.
// ¡Puede afectar al rendimiento! Se debe usar con cuidado (throttling).
window.addEventListener('scroll', () => {
  if (window.scrollY > 100) {
    // mostrar un botón de "volver arriba"
  }
});

// 'resize': Se dispara cuando se redimensiona la ventana.
window.addEventListener('resize', adaptarLayout);

El Objeto `event`

La función manejadora siempre recibe un argumento de forma automática: el objeto `event`. Contiene información valiosísima sobre la interacción que acaba de ocurrir.

elemento.addEventListener('click', function(event) {
  // 'event' es un objeto lleno de propiedades útiles
  console.log(event);
});
14 / 30

`event.target` y `event.currentTarget`

`event.target`: Es el elemento específico que originó el evento. Si tienes un div con un botón dentro, y haces clic en el botón, `event.target` será el botón.

`event.currentTarget`: Es el elemento donde el `addEventListener` está adjuntado. En el mismo ejemplo, sería el div.

divContenedor.addEventListener('click', function(event) {
  console.log(event.target);       // Puede ser el botón, un p, etc.
  console.log(event.currentTarget); // Siempre será divContenedor
});
15 / 30

`event.preventDefault()`

Cancela el comportamiento por defecto del navegador para un evento. Esencial para manejar envíos de formularios y clics en enlaces con JavaScript.

const link = document.querySelector('a');
const form = document.querySelector('form');

link.addEventListener('click', function(event) {
  event.preventDefault(); // Evita la navegación a la URL del enlace
  console.log('Navegación cancelada.');
});

form.addEventListener('submit', function(event) {
  event.preventDefault(); // Evita la recarga de la página
});

El Flujo de Eventos: Captura y Burbujeo

Cuando un evento ocurre (ej: un clic en un botón), no solo ocurre en ese botón. El evento viaja a través de sus ancestros en el DOM. Este viaje tiene dos fases.

Fase de Captura (hacia abajo): window -> document -> body -> div -> botón
Fase de Burbujeo (hacia arriba): botón -> div -> body -> document -> window
17 / 30

Fase de Burbujeo (Bubbling)

Por defecto, `addEventListener` escucha los eventos en la fase de burbujeo. Esto significa que el evento se dispara primero en el elemento más interno (`event.target`) y luego "burbujea" hacia arriba a través de sus padres.

// Si haces clic en el botón, verás los logs en este orden:
// 1. "Clic en el Botón"
// 2. "Clic en el Div"
// 3. "Clic en el Body"
body.addEventListener('click', () => console.log('Clic en el Body'));
div.addEventListener('click', () => console.log('Clic en el Div'));
boton.addEventListener('click', () => console.log('Clic en el Botón'));
18 / 30

Fase de Captura (Capturing)

Podemos decirle a `addEventListener` que escuche en la fase de captura pasando un tercer argumento. Es menos común, pero útil en ciertos escenarios.

// Al hacer clic en el botón, el orden ahora se invierte:
// 1. "Captura en el Body"
// 2. "Captura en el Div"
// 3. "Burbujeo en el Botón"
body.addEventListener('click', ..., { capture: true });
div.addEventListener('click', ..., { capture: true });
boton.addEventListener('click', ..., { capture: false }); // o por defecto
19 / 30

`event.stopPropagation()`

Este método detiene la propagación del evento, es decir, evita que siga burbujeando (o capturándose) hacia los ancestros.

div.addEventListener('click', () => console.log('Clic en el Div'));

boton.addEventListener('click', function(event) {
  event.stopPropagation(); // ¡Detiene la burbuja aquí!
  console.log('Clic en el Botón');
});

// Al hacer clic en el botón, solo se verá "Clic en el Botón".
// El listener del div nunca se enterará del evento.

Patrón Avanzado: Delegación de Eventos

Problema: ¿Qué pasa si tienes una lista con 100 ítems y quieres que cada uno reaccione al clic? ¿Añadir 100 `addEventListener`? ¡No! Es ineficiente.

Solución: Aprovechar el burbujeo. Se añade un solo `addEventListener` al contenedor padre.

  <li>Comprar pan</li>
  <li>Pasear al perro</li>
  <li>Estudiar JavaScript</li>
</ul>

Delegación de Eventos en Práctica

Dentro del manejador del padre, usamos `event.target` para identificar qué hijo fue el que realmente originó el clic.

const lista = document.querySelector('#lista-tareas');

lista.addEventListener('click', function(event) {
  // Comprobamos si el elemento clickeado es un LI
  if (event.target.tagName === 'LI') {
    // Aplicamos el estilo solo al LI que se clickeó
    event.target.style.textDecoration = 'line-through';
  }
});
22 / 30

Ventajas de la Delegación

1. Mejor rendimiento: Menos "escuchadores" consumen menos memoria.
2. Maneja elementos dinámicos: Si añades nuevos `

  • ` a la lista con JavaScript, la delegación funcionará automáticamente para ellos, sin necesidad de añadirles un nuevo listener.

    // Este nuevo LI funcionará con el listener del padre
// sin necesidad de hacer nada más.
const nuevoItem = document.createElement('li');
nuevoItem.textContent = 'Nuevo item dinámico';
lista.append(nuevoItem);

    Eliminar Event Listeners

    Para evitar "fugas de memoria" (`memory leaks`), es buena práctica eliminar los listeners que ya no se necesitan usando `removeEventListener`.

    elemento.removeEventListener('tipoDeEvento', funcionManejadora);

// ¡Importante! Debes pasarle exactamente la misma función
// que usaste en addEventListener. No funciona con
// funciones anónimas.
    24 / 30

    `removeEventListener`: Ejemplo

    Para poder eliminar un listener, la función manejadora debe ser una función con nombre, no una anónima.

    const boton = document.querySelector('#mi-boton');

function manejadorDeClic() {
  console.log('Clic!');
  // Tras el primer clic, eliminamos el listener
  boton.removeEventListener('click', manejadorDeClic);
}

boton.addEventListener('click', manejadorDeClic);

// Esto NO se podría eliminar:
// boton.addEventListener('click', () => console.log('clic'));

    Eventos Personalizados

    JavaScript nos permite crear y disparar nuestros propios eventos. Esto es muy útil para desacoplar componentes y mejorar la arquitectura de aplicaciones complejas.

    // 1. Crear un nuevo evento
const miEvento = new CustomEvent('datosCargados', {
  detail: { id: 123, status: 'ok' } // 'detail' puede llevar datos
});

// 2. Un elemento escucha nuestro evento personalizado
document.addEventListener('datosCargados', function(event) {
  console.log('Datos recibidos:', event.detail);
});

// 3. Otro lugar del código dispara (dispatch) el evento
document.dispatchEvent(miEvento);

    Eventos de Puntero (`Pointer Events`)

    Son una evolución moderna de los eventos de ratón. Unifican el manejo de interacciones de ratón, lápiz táctil y dedos (touch) en un solo conjunto de eventos.

    'pointerdown'   // Se presiona (ratón, dedo, lápiz)
'pointerup'     // Se levanta
'pointermove'   // Se mueve
'pointerenter'  // Entra al área
'pointerleave'  // Sale del área

// Usarlos simplifica el código para dispositivos táctiles y de escritorio.

    Eventos de Transición y Animación

    Podemos ejecutar código JavaScript cuando una transición o animación de CSS termina.

    const caja = document.querySelector('.animada');

// Se dispara cuando una transición CSS finaliza
caja.addEventListener('transitionend', () => {
  console.log('La transición ha terminado.');
  caja.classList.remove('moviendose');
});

// 'animationend': el equivalente para animaciones con @keyframes

    Buenas Prácticas

    1. Usa `DOMContentLoaded` para iniciar tus scripts.
    2. Prefiere la delegación de eventos para listas y elementos dinámicos.
    3. Usa `event.preventDefault()` en formularios.
    4. Elimina listeners (`removeEventListener`) si ya no los necesitas (ej: en Single Page Apps al cambiar de "página").
    5. Ten cuidado con eventos "ruidosos" como `scroll` y `mousemove`.

    // La delegación es uno de los patrones
// más importantes y útiles en la gestión de eventos.
